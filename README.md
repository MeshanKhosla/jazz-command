# Jazz Command

Jazz Command is a small web controller for a Bluetooth speaker attached to a Linux home server. Open the dashboard to play music, change the volume, check the speaker connection, and set weekly play times.

The app runs on port `8787`. Open `http://<server-ip>:8787` from another device on the home network.

## What it does

- Connects to a configured Bluetooth speaker
- Plays Radio Swiss Jazz through `mpv`
- Finds audio files under `music/` and `~/Music`
- Shows current playback and Bluetooth status
- Saves volume and schedules to disk
- Starts the weekday radio schedule at 8:00 AM
- Runs after logout and starts again after a reboot

Scheduled playback has no automatic stop time yet. It continues until you press Stop, start another source, or stop the service.

## Use the dashboard

Open one of these addresses in a browser:

- On this laptop: [http://localhost:8787](http://localhost:8787)
- On another device connected to the same network: `http://<server-ip>:8787`

The large player shows what Jazz Command is doing. Press Play radio to start Radio Swiss Jazz. Press any row under Available music to play that source instead.

The volume slider writes the chosen level to `data/config.json` and changes the current PipeWire output volume.

### Add local music

Copy supported audio files into either of these directories:

```text
music/    Music stored beside the app
~/Music   Music shared from your home directory
```

Jazz Command scans both directories whenever the browser asks for fresh status. New files appear without a restart. Git ignores audio under `music/`, so adding an album will not add it to your next commit.

Supported extensions are:

```text
mp3  flac  m4a  ogg  opus  wav
```

Folders appear as the smaller description below each track name.

### Add a schedule

1. Press Add set.
2. Enter a name and start time.
3. Choose a music source and at least one day.
4. Press Save schedule.

The server checks schedules every 15 seconds. It records the date after starting a set, which prevents the same schedule from firing more than once that day. Times use the laptop's local time zone, currently `America/Los_Angeles`.

The included schedule plays Radio Swiss Jazz at 8:00 AM every Monday through Friday.

### Starter content

The tracked file `config/defaults.json` defines the starter library and schedule. Every clone begins with Radio Swiss Jazz and the weekday 8:00 AM set.

Radio Swiss Jazz is a live internet stream. It has a URL in the defaults file, not an audio file under `music/`. On the first launch, Jazz Command copies the starter schedule and volume into `data/config.json`. That runtime file belongs to each installation and stays out of Git.

Edit `config/defaults.json` when you want future installations to start with another public radio stream or schedule. Existing installations keep their saved schedules in `data/config.json`.

## Configure the speaker

Jazz Command reads the speaker address and PipeWire output from environment variables:

```text
JAZZ_SPEAKER=AA:BB:CC:DD:EE:FF
JAZZ_SPEAKER_NAME=Tune Table
JAZZ_AUDIO_DEVICE=pipewire/bluez_output.AA_BB_CC_DD_EE_FF.1
```

Run `mpv --audio-device=help` to find the exact PipeWire output name. The example systemd service in `deploy/jazz-command.service.example` shows where to set these values.

## How it works

The dashboard uses React. Vite bundles it into `dist`, which the Node server sends to the browser. The server uses Node's built-in HTTP module for the JSON API, scheduler, and static files.

When playback starts, the server follows this sequence:

1. Check the Tune Table connection with `bluetoothctl`.
2. Connect the speaker if it is offline.
3. Start `mpv` as a child process.
4. Send audio straight to the Tune Table PipeWire output.
5. Keep `mpv` alive inside the Jazz Command systemd service.

Starting another source stops the current `mpv` process first. The Stop button also sends that process `SIGTERM`.

The main files are:

```text
server.js         HTTP API, Bluetooth control, playback, and scheduler
config/defaults.json  Starter stations, schedule, and volume
src/App.jsx       React controls, schedules, and music library
src/styles.css    Responsive dark console design
index.html        Vite HTML entry point
dist/             Production browser files generated by Vite
data/config.json  Saved volume and schedules
music/            Optional local audio directory
```

## Development

Install packages and start the Vite development server:

```bash
cd ~/Code/jazz-command
npm install
npm run dev
```

Vite runs at `http://localhost:5173` and sends API requests to the production server on port `8787`.

Build the files used by the system service:

```bash
npm run build
systemctl --user restart jazz-command.service
```

Run the syntax check and production build together with `npm run check`.

The API routes are:

```text
GET    /api/state             Current speaker, player, library, and schedule state
POST   /api/play              Start a source by sourceId
POST   /api/stop              Stop playback
POST   /api/volume            Save and apply a volume from 0 through 100
POST   /api/schedules         Add or update a schedule
DELETE /api/schedules/:id     Delete a schedule
```

## Service management

The user service lives at:

```text
~/.config/systemd/user/jazz-command.service
```

Useful commands:

```bash
systemctl --user status jazz-command.service
systemctl --user restart jazz-command.service
systemctl --user stop jazz-command.service
journalctl --user -u jazz-command.service -f
```

After changing the service file, reload it before restarting:

```bash
systemctl --user daemon-reload
systemctl --user restart jazz-command.service
```

The service binds to `0.0.0.0:8787`, which makes it reachable through every network interface on the laptop. systemd user lingering is enabled for `meshan`, so the service can run without an open desktop session.

## Troubleshooting

### The page does not open

Check the service and port:

```bash
systemctl --user status jazz-command.service
curl http://127.0.0.1:8787/api/state
```

If localhost works but another device cannot connect, confirm both devices are on the same network. The laptop's address may also have changed. Run `ip -brief address show scope global` to find its current address.

### The page says the speaker is offline

Turn on Tune Table and keep it within Bluetooth range. Then press Play again. Jazz Command will try to reconnect it.

To test the connection by hand:

```bash
bluetoothctl connect AA:BB:CC:DD:EE:FF
```

Some portable speakers turn themselves off after a period of silence. Software cannot wake a speaker that has powered off completely.

### Playback starts on the laptop speakers

List the PipeWire outputs:

```bash
wpctl status
```

Tune Table should appear under Sinks and have an asterisk beside it. Reconnect it with `bluetoothctl`, then try playback again.

### A local track does not appear

Confirm that the file is under `~/Music` and uses one of the supported extensions. The scanner ignores hidden files and directories.

## Security

Jazz Command has no login screen or access token. Anyone who can reach port `8787` can control playback and change schedules. Keep it on a trusted home network. Do not forward this port through the router or expose it to the public internet.
